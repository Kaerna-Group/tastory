## Как вести документы

Этап 2: схема, [перенос пользователей](users-import-staging.md), доступ по таблицам и [журнал](operation-journal.md) подтверждены. Реализовано [управление приглашениями и правами](access-management.md); положительный прогон новых действий на настоящих аккаунтах подтверждается отдельно. Далее — первый структурированный рецепт.

- Руководство описывает текущее поведение, roadmap — будущее.
- Проверку помечаем выполненной только при наличии результата. Mock не доказывает работу Google.
- Для долгосрочного решения создаём ADR по [шаблону](adr/template.md).
- Следующую задачу выбираем из backlog; закрытую отмечаем с датой и доказательством.
- Не записываем токены, credentials, пользовательские данные и приватные ID.
- Blueprint не дублируем: ссылаемся на его раздел и описываем принятое решение.
