Полная сверка с blueprint, таблица критичности модулей и порядок реализации: [отчёт на 3 сентября 2026](project-status-2026-09-03.md).

[Библиотека R-06](recipe-library.md): сетка/список, поиск по названию и ингредиентам, фильтры, сортировка, URL-состояние и личное избранное в схеме 5.

## Как вести документы

Этап 2: схема, [перенос пользователей](users-import-staging.md), доступ по таблицам, [журнал](operation-journal.md) и [управление приглашениями и правами](access-management.md) подтверждены владельцем. Это функциональная приёмка текущего модуля, без объявления всех production-условий выполненными. Далее — первый структурированный рецепт.

- Руководство описывает текущее поведение, roadmap — будущее.
- Проверку помечаем выполненной только при наличии результата. Mock не доказывает работу Google.
- Для долгосрочного решения создаём ADR по [шаблону](adr/template.md).
- Следующую задачу выбираем из backlog; закрытую отмечаем с датой и доказательством.
- Не записываем токены, credentials, пользовательские данные и приватные ID.
- Blueprint не дублируем: ссылаемся на его раздел и описываем принятое решение.
