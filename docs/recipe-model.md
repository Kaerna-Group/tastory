# Модель рецепта и объектные права — R-01

Реализовано в коде 3 сентября 2026: контракты, целостность агрегата, матрица прав и серверный слой чтения/проверки действий. [R-02](recipe-storage.md) подключает этот модуль к Google Sheets, миграции и HTTP API; его код также реализован и проверен локально. Экран рецепта относится к R-04, опубликованный сайт пока не создаёт рецепты. Ниже описан самостоятельный слой модели и прав.

## Содержание

- `Recipe`: UUID, тетрадь, автор, название, описание, порции, время подготовки/готовки, источник HTTP(S), личные заметки, видимость, статус, даты и ревизия.
- `RecipeIngredient`: собственный UUID, ссылка на рецепт, секция, позиция, название, числовое количество или текст «по вкусу», единица, примечание, опциональность, даты и ревизия.
- `RecipeStep`: собственный UUID, ссылка на рецепт, секция, позиция, текст, необязательный таймер, даты и ревизия.
- `Tag`: UUID, тетрадь, создатель, имя, нормализованное имя, безопасный цветовой токен, active/archived, даты и ревизия. Теги — общий справочник тетради; связи с личными рецептами не выдаются вместе с ним.
- `RecipeTag`: составной ключ recipeId/tagId, назначивший пользователь, даты и ревизия.

`RecipeAggregate` содержит рецепт целиком, ингредиенты, шаги, теги и их связи. Проверяются уникальность идентификаторов и позиций, настоящий родитель каждого дочернего объекта, соответствие тетради тегов, отсутствие повторных/оборванных связей и нормализованных дубликатов тегов. Позиция задаёт порядок независимо от порядка строк хранилища. UUID разных типов имеют отдельные пространства идентификаторов.

Пустые ингредиенты/шаги допускаются для начального рецепта. Пределы: 200 ингредиентов, 100 шагов, 30 тегов. Порции и количество — положительные числа; время — целое неотрицательное. Отсутствующее число обозначается `null`. В R-01 описание, шаги и заметки — простой текст; rich text, файлы и визуальный документ добавляются своими модулями.

## Матрица доступа

Правила следуют blueprint §14.3: private доступен автору и владельцу тетради. Отдельной роли admin в текущем приложении нет. Владелец тетради имеет доступ и к личным рецептам участников.

| Действие                                          | Owner тетради            | Member — автор           | Другой member       | Viewer             |
| ------------------------------------------------- | ------------------------ | ------------------------ | ------------------- | ------------------ |
| Читать private                                    | Да                       | Да                       | Нет                 | Только собственный |
| Читать workspace                                  | Да                       | Да                       | Да                  | Да                 |
| Создать рецепт                                    | Да                       | Да                       | Да, от своего имени | Нет                |
| Изменить содержание/видимость                     | Да                       | Да                       | Нет                 | Нет                |
| Опубликовать, архивировать, удалить, восстановить | Да                       | Да                       | Нет                 | Нет                |
| Читать личные заметки                             | Да                       | Да                       | Нет                 | Только собственные |
| Читать справочник тегов                           | Да                       | Да                       | Да                  | Да                 |
| Создать тег                                       | Да                       | Да                       | Да                  | Нет                |
| Изменить/архивировать/восстановить тег            | Да                       | Если создал тег          | Если создал тег     | Нет                |
| Назначить/снять тег                               | Если можно менять рецепт | Если можно менять рецепт | Нет                 | Нет                |

Все права ограничены текущей тетрадью и активным пользователем/членством. Роль viewer запрещает запись даже в собственный рецепт, например после понижения роли автора. Статусы draft/published допускают изменение; публикация — только из draft. Архив можно читать, восстановить или мягко удалить, но нельзя редактировать. Deleted исключён из чтения и списков; восстановление разрешено автору с правом записи и owner. Операции перехода статуса проверяются здесь; запись переходов и выбор статуса при восстановлении — R-02.

Архивные теги остаются читаемыми в существующем рецепте. Их можно сохранить в неизменной связи или снять, но нельзя назначить заново. Имя архивного тега остаётся занятым в справочнике.

## Серверная граница

`services/recipe-model.ts` принимает проверенную Google-сессию, серверный workspaceId, загрузчик текущего каталога пользователей и `RecipeModelReader`. Для каждого вызова повторно проверяет срок сессии, структуру каталога, активность пользователя и членства. `AuthData.user.id` — Google sub; он разрешается в внутренний Users.user_id. Переданная в сессии роль не используется для разрешения действия. После чтения срок сессии проверяется ещё раз.

- `readRecipeAggregate` сначала проверяет рецепт, затем возвращает валидированный агрегат. Личные заметки очищаются при чтении другим участником.
- `listRecipeSummaries` фильтрует доступ и строит явную лёгкую проекцию без заметок, ингредиентов и шагов. Она пригодна для общей библиотеки без утечки личных заметок в поиск.
- `authorizeRecipeObject` проверяет рецепт, ингредиент, шаг, тег или конкретную связь. Родитель ингредиента/шага берётся только из хранилища. При чтении/удалении связи проверяются оба конца.
- `authorizeRecipeCreate` определяет автора и тетрадь на сервере. Входные схемы запрещают передавать роль, владельца, родительские ссылки, даты и ревизии объектов; новые UUID назначает будущий writer.
- `authorizeRecipeUpdate` проверяет текущую ревизию и принадлежность всех переданных дочерних UUID этому рецепту. Новый дочерний объект передаётся без ID. Обновление содержания не меняет видимость или статус.
- `authorizeRecipeTagAssignment` проверяет право менять рецепт, доступность и активность тега; `authorizeTagCreate` нормализует имя и проверяет уникальность.

Отсутствующий и недоступный объект возвращают одинаковый `ACCESS_DENIED`; некорректный вход — `RECIPE_INVALID`, повреждение модели — `RECIPE_UNAVAILABLE`, устаревшая ревизия/занятое имя — `RECIPE_CONFLICT`. Эти ошибки пока внутренние: новые действия не добавлены в HTTP allowlist.

Пользователи, записанные как автор/создатель/назначивший, должны существовать в каталоге и иметь запись членства в соответствующей тетради. Их отключение не уничтожает исторические рецепты и связи. Активность обязательна для текущего действующего пользователя.

Reader обязан возвращать согласованный снимок и корректно искать сущности по ключам. Адаптер R-02 вызывает проверку прав и запись под одной блокировкой, заново проверяет права при повторе операции и не использует ранее возвращённые объекты как сохранённое разрешение. Журнал, аудит и восстановление частичных записей реализованы в R-02, отдельно от слоя модели.

## Проверки

Тесты покрывают private/workspace, все роли, статусы, подмену ID, чужие тетради, шаги и ингредиенты, оба конца связей, отключение пользователя/членства, устаревшую роль, истечение сессии, Google sub → внутренний UUID, утечку заметок, порядок, ревизии, дубликаты и повреждение агрегата. Серверный модуль включён в общий coverage gate.

```sh
npx vitest run packages/contracts/src/recipe.test.ts packages/domain/src/recipe-access.test.ts apps/apps-script/src/services/recipe-model.test.ts
```
