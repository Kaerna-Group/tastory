# Библиотека шаблонов рецепта V-02

Модуль сохраняет десять исходных композиций страницы и добавляет четыре новых книжных семейства для блюд. Шаблон меняет расположение и декоративную подачу рецепта, а при применении сохраняет снимок цветов, шрифтов и бумаги действующей темы страницы. Содержание рецепта хранится отдельно и при выборе оформления не изменяется. Полный просмотр и карточки каталога используют общий [renderer книжных страниц](recipe-pages.md).

## Встроенная коллекция

| Блюда              | Напитки           |
| ------------------ | ----------------- |
| Тёплый очаг        | Домашняя кофейня  |
| Городское бистро   | Чайная церемония  |
| Сад и травы        | Коктейльный вечер |
| Праздничная подача | Свежий бар        |
| Семейная тетрадь   | Винный погреб     |
| Пастельный блокнот |                   |
| Ягодный дневник    |                   |
| Линованная тетрадь |                   |
| Чистая карточка    |                   |

Четыре новых варианта следуют [ADR 0010](adr/0010-reference-led-book-families.md). Десять прежних ID
не переопределяются, поэтому уже сохранённые рецепты продолжают выглядеть как раньше.

Все композиции используют только известный идентификатор layout. Произвольный CSS, HTML, URL и сетевые шрифты в шаблон не попадают, поэтому пользовательский вариант не может изменить интерфейс приложения или выполнить код. Один renderer поддерживает светлые, тёмные и пользовательские темы через семантические переменные цветов.

## Личная и общая библиотека

Участник может создать до 30 собственных шаблонов на основе любой встроенной композиции. Для обычного сценария достаточно названия, основы, короткого описания и выбора «Только мне» или «Поделиться с участниками». Создание и архив находятся в блоке дополнительных действий, чтобы основной экран оставался простым.

Общий шаблон видят активные участники книги. Кнопка «Сохранить себе» создаёт независимую личную копию с новым UUID и ссылкой `sourceTemplateId` на источник. Дальнейшее изменение или архивирование источника не меняет копию. Личный шаблон читают его автор и владелец книги; `viewer` видит разрешённые шаблоны, но не создаёт, не копирует и не применяет их.

Сервер возвращает общую библиотеку страницами не более 100 записей через `offset`, `limit` и
`nextOffset`. Права, фильтры и стабильная сортировка применяются до разбиения. Интерфейс автоматически
дочитывает все страницы, поэтому суммарные шаблоны нескольких участников не упираются в лимит одного
ответа. Старый запрос без параметров страницы остаётся допустимым только пока результат помещается в
один ответ; при большем наборе сервер возвращает явную ошибку вместо молчаливого обрезания.

## Данные и надёжность

Миграция `008-recipe-templates` переводит книгу со схемы 7 на 8 и добавляет три листа:

- `Templates` — неизменяемые версии пользовательских шаблонов, видимость, источник и ревизия;
- `RecipeTemplates` — применённый к рецепту снимок имени, категории, layout, темы и автора источника;
- `TemplateOperations` — requestId, хеш команды и единственная ячейка публикации операции.

Каждая запись сначала получает состояние `started`, дописывает отсутствующую версию и становится видимой только после `committed@…`. Безопасный повтор того же requestId возвращает `replayed`; другой payload с тем же ID отклоняется. Применение требует актуальную ревизию оформления и право на изменение рецепта.

Клиент создаёт requestId до отправки и сохраняет неизменяемую pending-команду в `localStorage` в
области конкретных API endpoint и subject аккаунта. Токены и другие учётные данные туда не попадают.
Неизвестный результат (обрыв транспорта, некорректный ответ или размонтирование) оставляет команду для
повтора с тем же requestId после повторного входа или перезагрузки. Подтверждённый успех либо явный
отказ завершают команду. Ошибка последующего обновления списка показывается отдельно и не предлагает
повторить уже завершённую запись.

Применение оформления сравнивает сразу две ожидаемые ревизии: содержание рецепта и его оформление.
Значение `null` означает, что оформление ещё не применялось. Для перехода с API v1 отсутствие поля
принимается только при первом применении; после появления оформления такой запрос получает конфликт.
Frontend сначала проверяет `templates.capabilities` протокола v3 и не разрешает небезопасную работу со
старым Apps Script backend. Поэтому выпуск выполняется в порядке backend, затем frontend.

Снимок отделён от источника. Изменение, архивация или удаление доступности пользовательского шаблона не ломают уже оформленные рецепты. Три листа шаблонов входят в проверку структуры, резервное копирование и восстановление книги.

Миграция `009-recipe-designs` переводит схему 8 на 9 и добавляет `RecipeDesigns`. Эта запись имеет
собственную ревизию, хранит версионированные layout/theme/elements и публикуется через ту же
идемпотентную `TemplateOperations`. Она не содержит HTML или текста рецепта. Подробная граница
авторских и вычисляемых данных описана в [ADR 0007](adr/0007-durable-recipe-design.md).

## Интерфейс и проверка

В сохранённом рецепте показан живой предпросмотр с реальным названием, описанием, временем, ингредиентами и шагами. Каталог поддерживает поиск и разделы «Все», «Блюда», «Напитки», «Мои» и «От участников». На телефоне карточки и предпросмотр переходят в одну колонку без горизонтального переполнения.

Перед живым использованием:

1. Отдельно согласовать вход владельцем и применить additive-миграцию схемы 9; frontend deployment
   не развёртывает Apps Script и не должен неявно запускать миграцию.
2. Под участником создать личный и общий шаблон; проверить видимость у владельца и читателя.
3. Под другим участником сохранить общий шаблон себе, затем изменить источник и проверить независимость копии.
4. Применить встроенный и пользовательский шаблон к рецепту, повторно открыть рецепт и проверить сохранённый layout.
5. Создать и проверить резервную копию книги с таблицами шаблонов и `RecipeDesigns`.

Текущий V-02 сохраняет выбранную композицию. V-01 уже создаёт из неё одну или несколько читаемых страниц A4 и печатает тот же результат. Свободное перемещение произвольных блоков и визуальная отмена действий остаются следующим этапом модели страниц.
