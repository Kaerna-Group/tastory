# Google staging: запуск владельцем

Состояние на 2 сентября 2026 года: **Apps Script создан, код загружен. Владелец подтвердил успешный запуск setupStaging и открытие таблицы и папки.** S0-01 закрыт по подтверждению владельца; независимая проверка данных через API ещё не выполнена.

Следующий шаг — [опубликовать staging web app](apps-script.md#публикация-staging-web-app). Проверка Google API обнаружила только HEAD deployment без web app entrypoint: опубликованного URL `/exec` пока нет. Clasp подключён для работы с кодом; разрешения Drive/Sheets для выполнения скрипта владелец выдал в редакторе.

Точная ссылка на созданный проект находится в локальном `.local/google-staging.md` и в ответе задачи. Этот файл и `.clasp.json` исключены из Git.

## Первоначальный запуск и повторная проверка

1. Откройте **Tastory - Staging API** по выданной ссылке под аккаунтом, которому принадлежит проект.
2. В редакторе откройте файл **Code**. В списке функций над кодом выберите **setupStaging**.
3. Нажмите **Выполнить / Run**. При первом запуске Google предложит проверить разрешения: выберите аккаунт владельца и подтвердите доступ к Google Sheets и Drive для своего проекта Tastory.
4. Если после выдачи разрешений выполнение не началось, ещё раз нажмите **Выполнить**.
5. Дождитесь сообщения об успешном завершении. В **Журнале выполнения / Execution log** появится JSON с `spreadsheetUrl` и `assetFolderUrl`. Откройте обе ссылки и проверьте названия.

Ожидаемый результат:

| Ресурс        | Название                 | Назначение                                           |
| ------------- | ------------------------ | ---------------------------------------------------- |
| Apps Script   | Tastory - Staging API    | Серверный код и настройки staging                    |
| Google Sheets | Tastory - Staging DB     | Пустая тестовая таблица; схема данных появится позже |
| Google Drive  | Tastory - Staging Assets | Отдельная папка для тестовых фотографий              |

Таблица и папка создаются в «Моём диске» владельца. Функция не включает общий доступ. Вручную создавать эти два ресурса или копировать их ID в настройки не требуется.

После запуска сообщите результат: успешно ли завершилось выполнение и открываются ли обе ссылки. При ошибке достаточно её текста без содержимого credentials.

## Что делает setupStaging

- Берёт блокировку проекта, чтобы два запуска настройки не работали одновременно.
- Проверяет `APP_ENV`: допускает только staging или новый проект без привязанных ресурсов.
- Создаёт таблицу и папку при отсутствии записанных ID. Сохраняет каждый ID сразу после создания ресурса.
- При повторном запуске открывает ресурсы по сохранённым ID. Если папка не создалась, а ID таблицы уже сохранён, повторный запуск продолжит с папки.
- При недоступности ранее сохранённого ресурса завершает работу с ошибкой; замена автоматически не создаётся.
- Выводит ссылки в журнал редактора и освобождает блокировку.

В **Project Settings → Script Properties** появятся:

| Свойство             | Значение                                   |
| -------------------- | ------------------------------------------ |
| `APP_ENV`            | `staging`                                  |
| `SPREADSHEET_ID`     | ID созданной таблицы                       |
| `DRIVE_FOLDER_ID`    | ID созданной папки                         |
| `DEPLOYMENT_VERSION` | `staging-foundation`, если ранее не задано |
| `ENABLE_SPIKE_ECHO`  | `false`, если ранее не задано              |

Имена ресурсов используются только при создании; поиск и повторное использование происходят по ID. Не удаляйте свойства для повторного запуска. Если ресурс создан, но сохранение его ID завершилось ошибкой, сначала проверьте «Мой диск» и восстановите привязку, чтобы не создать дубликат.

`setupStaging` запускается из редактора владельцем. В публичном RPC нет такого action; HTTP-запрос его не выполняет. OAuth scopes определяются Apps Script по используемым сервисам; нативный `DriveApp` запрашивает доступ к Drive, а не только к новой папке. Пользовательские рецепты и фотографии пока не обрабатываются.

## Что сделать после создания ресурсов

1. Успешное создание уже зафиксировано в S0-01 [чек-листа](spike-checklist.md) по подтверждению владельца.
2. Создать staging web app deployment по [инструкции Apps Script](apps-script.md#публикация-staging-web-app).
3. Подключить URL `/exec` к web-приложению и проверить GET/POST после redirect.
4. Продолжить проверки Google Sign-In, приглашений, приватных фото и конкурентной записи.

Создание ресурсов не закрывает технический gate: схема остаётся версии `0`, health пока сообщает `storage: not-configured` и `auth: not-configured`. Проверка доступности хранилища из API, миграции и пользовательская авторизация — отдельные задачи.
