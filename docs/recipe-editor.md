# Редактор, черновики и автосохранение — R-03 / основа R-04

Реализовано в рабочей копии 3 сентября 2026. После входа библиотека показывает доступные серверные рецепты и локальные копии текущего аккаунта. «Новый рецепт» открывает редактор названия, описания, порций, времени, ингредиентов, шагов, тегов из справочника, источника и личных заметок. Ингредиенты и шаги можно добавлять, удалять, перемещать и объединять названием раздела. Видимость выбирается до первого сохранения; по умолчанию рецепт личный.

Маршруты: `/#/drafts/:id` — локальный черновик, `/#/recipes/:id` — серверный рецепт. Экраны работают на телефоне и компьютере. Редактирование существующего рецепта включается по `recipes.get.permissions.edit`; отсутствие capabilities в старом ответе означает режим чтения. Сервер по-прежнему проверяет актуальное членство и каждый объект при записи. Архивирование/восстановление остаётся доступно через API R-02; кнопки этих действий, создание тегов и изменение видимости существующего рецепта не входят в текущий экран.

## Локальная копия и очередь

- Каждая правка синхронно заменяет один JSON-документ в `localStorage`. Ключ содержит версию формата, URL API, Google subject и UUID черновика. Пароль/Google credential не сохраняется; приложение не показывает копии другого аккаунта или другого сервера. API URL обозначает подключённую тетрадь.
- Документ содержит текущие поля, последнюю известную серверную версию, счётчик правок, конфликт и максимум один неизменяемый запрос в очереди. Сначала записывается запрос с UUID, затем вызывается API. Поля с незавершённым текстом/ссылкой/числом сохраняются локально, а серверная валидация откладывает отправку до исправления.
- После паузы ввода 900 мс запускается сохранение. В полёте находится одна запись; более свежие правки объединяются в следующую. Кнопка «Сохранить сейчас» запускает тот же механизм.
- После квитанции клиент читает агрегат и связывает новые серверные ID ингредиентов/шагов с локальными ключами отправленного снимка. Правки, сделанные за время отправки, остаются в следующем снимке. Если сервер уже содержит более позднюю версию, показывается конфликт вместо привязки ID по чужому порядку.
- При потере квитанции или последующего чтения повторяются прежние тело и requestId. Перезагрузка не создаёт новый запрос создания. Повторы временных ошибок: 1, 2, 4…30 секунд; событие восстановления сети возобновляет очередь. Ошибки доступа/лимита/чужой незавершённой операции требуют повторного входа либо устранения причины и ручного повтора.
- При уходе из редактора запрос прерывается, но очередь остаётся локально. Она продолжится при следующем открытии. Невыполненные черновики не отправляются в фоне из библиотеки.
- После перезагрузки нужен повторный вход в тот же аккаунт: credential существует только в памяти. Черновик восстанавливается из браузера. Загрузка оболочки и повторный вход требуют сети; кеш оболочки/PWA не реализован этим модулем.

`navigator.locks` удерживает исключительную блокировку черновика до закрытия редактора. Вторая вкладка с тем же черновиком получает объяснение и кнопку повторного открытия. Разные локальные копии одного серверного рецепта защищаются серверной ревизией. Браузер без Web Locks не допускает редактирование.

## Конфликты и сбои устройства

При несовпадении ревизии автосохранение останавливается. Экран показывает локальный и серверный текст, ингредиенты, шаги, теги, время, источник и заметки. Можно продолжить со своими правками поверх показанной серверной версии либо принять серверную. Оба выбора сначала сохраняют прежние локальные правки отдельным личным черновиком. Известная собственная незавершённая операция отменяется перед новым запросом. Повторное изменение сервера снова вызовет конфликт.

При переполнении/отказе хранилища отправка останавливается; UI не сообщает об успешной локальной записи. Последняя версия остаётся в памяти с тем же ключом аккаунта, переживает переходы внутри приложения и доступна для скачивания JSON. Перед перезагрузкой/закрытием браузер предупреждает о риске потери. После освобождения места «Повторить сохранение» сначала записывает копию на устройство. Внезапное завершение браузера может потерять только эту явно несохранённую версию в памяти.

«Скачать копию» выгружает локальные поля и известные серверные версии без credential. Это аварийный экспорт; импорт JSON отдельным файлом пока не реализован. Повреждённые или неизвестные версии локальных документов не перезаписываются. Удаление локальной копии в библиотеке требует подтверждения и блокировки вкладки; копию с незавершённым запросом удалить через UI нельзя. Очистка данных сайта удалит локальные черновики. Копии не зашифрованы от владельца профиля браузера.

## Проверка и запуск

Unit-проверки покрывают сохранение до отправки, слияние очереди во время запроса, повтор потерянной квитанции/чтения после перезагрузки, незавершённые поля, отсутствие сети, отказ хранилища, восстановление памяти после навигации, права чтения, два решения конфликта и отмену собственной операции. Браузерные сценарии `auth-e2e/recipes.spec.ts` проверяют редактор, перезагрузку/повторный вход, потерю ответа, конфликты, две вкладки, другой аккаунт, viewer и скачивание при переполнении на desktop/mobile Chromium. Google-провайдер и HTTP API в этих сценариях подставные.

Итог проверки: 522 unit/contract-теста с coverage gate (95.97% строк, 89.35% ветвей), 38 auth-браузерных сценариев и 6 базовых smoke-сценариев. Типы, lint, архитектура, формат, web/Apps Script сборки и размеры JS прошли. Два теста отчёта входа повторно проверены после замены фиксированного порта на текущий origin. Браузерные процессы запускались с правами, необходимыми Playwright для остановки своего тестового сервера Windows.

Для Google нужен `npm run dev:staging`, опубликованный backend R-02 с capabilities R-03 и применённая миграция 003. Владелец может подготовить хранилище кнопкой в библиотеке, когда сервер возвращает `RECIPE_NOT_READY`. Эти изменения не публиковались и не запускали миграцию в рабочем Google-проекте. Mock-режим по-прежнему не имитирует авторизованный Google-аккаунт.

На Windows зарезервированные системой порты можно обойти: `$env:PLAYWRIGHT_AUTH_PORT='4293'; npm run test:auth -- recipes.spec.ts`. Базовые smoke-тесты используют отдельный `PLAYWRIGHT_PORT`.

Рабочие лимиты R-02 сохраняются. [O-01](recipe-history.md) добавляет перенос старых версий/квитанций в приватный архив и просмотр истории из редактора. [Минимум O-02](book-backups.md) добавляет копирование и отдельное восстановление книги. Живая приёмка и замеры задержек Google O-03 ещё предстоят; UI показывает ошибки лимита и сохраняет локальный текст.
