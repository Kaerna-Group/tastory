# Одновременные записи: staging

Проба S0-08 подготовлена 3 сентября 2026 года. Она проверяет сохранение состояния в Google Sheets под ScriptLock, отказ устаревшей версии и повтор операции без дубликатов. Это отдельная проверка платформы; схема рецептов и полноценный журнал операций ещё не реализованы.

Сервер опубликован в **Apps Script version 4**, исходный код `91ecc9f`. Настройки и отказы для неавторизованных/некорректных запросов проверены на настоящем API. [Отчёт выпуска](staging-verification.md#выпуск-пробы-одновременных-записей). **S0-08 выполнен:** владелец прислал успешный JSON и снимок 3 сентября 2026 года; [результат прогона](staging-verification.md#настоящий-прогон-одновременных-записей).

## Как повторить при необходимости

Первый прогон уже принят. Следующие шаги сохранены для будущих изменений; повторять сейчас не требуется.

1. Обновите [настройки Tastory](https://kaerna-group.github.io/tastory/#/settings) и войдите в Google.
2. Найдите **Одновременные изменения** и нажмите **Проверить одновременные записи**. Оставьте страницу открытой до завершения.
3. Ожидается сообщение **«Проверка пройдена»**, восемь результатов запросов, итоговая версия 2. Один запрос должен получить «Устаревшая версия отклонена», два повтора — «Повтор без дубликата».
4. Нажмите **Скачать результат** и пришлите файл либо снимок блока. Отчёт содержит только случайный ID пробы, этапы, версии и время; токен и профиль Google в него не попадают.

Если проверка прервалась, сохраните результат. Не считайте отсутствие ответа отменой записи: часть запросов могла выполниться. Следующий запуск получает новый ID и не переписывает предыдущую пробу.

## Что выполняет кнопка

| Шаг                                                 | Ожидаемый результат                               |
| --------------------------------------------------- | ------------------------------------------------- |
| Чтение нового runId                                 | Версия 0, операций нет                            |
| Две записи одновременно, обе ожидают версию 0       | Одна запись сохранена, другая отклонена; версия 1 |
| Чтение результата                                   | Сохранено значение победившей операции            |
| Повтор победившей операции с тем же ID              | Повтор без новой записи, версия 1                 |
| Повтор проигравшего значения с новым ID и версией 1 | Сохранено, версия 2                               |
| Повтор старой победившей операции                   | Версия остаётся 2, новое значение не откатывается |
| Итоговое чтение                                     | Версия 2, ровно две применённые операции          |

Два параллельных запроса дают две строки отчёта, поэтому всего их восемь. Браузер запускает запросы совместно; расписанием выполнения Apps Script управляет Google. Синхронное начало исполнения на стороне Google не предполагается.

## Хранение и границы

- Только `APP_ENV=staging`, действующий Google credential, уже привязанный `sub`, текущая роль owner. Приглашение и роль проверяются на каждом запросе; после ожидания блокировки повторно проверяется срок токена.
- Используется существующий `SPREADSHEET_ID`. Лист `_TastoryConcurrency` создаётся только при первой записи и имеет служебный заголовок `tastory.concurrency.v1`. Другие листы не изменяются. Существующий лист с другим заголовком, лишними колонками или повреждёнными данными вызывает отказ.
- Одна ячейка содержит JSON состояния, случайный runId, хеш Google sub и квитанции двух операций. Google sub, email и токен не записываются. Клиент получает только собственную пробу; номера строк и ID таблицы в API отсутствуют.
- ScriptLock охватывает чтение, проверку expectedRevision, поиск operationId, запись одной ячейки, flush и контрольное чтение. При ошибке блокировка освобождается. Состояние и квитанция операции не разнесены по нескольким ячейкам.
- Для одинакового operationId принимается только исходная пара expectedRevision/value. Другое содержимое даёт OPERATION_MISMATCH. Устаревшая новая операция возвращает outcome conflict без записи. Применённая старая операция возвращает replayed и текущее состояние, поэтому повтор не откатывает более новую версию.
- На один runId допускаются две применённые операции. Значения ограничены first/second; произвольный текст, формулы, чужой ownerKey и дополнительные поля отклоняются. В листе не более 100 проб на всех тестовых владельцев. При достижении лимита доступны чтение и повтор существующих операций, новый запуск отклоняется.
- Старые пробы сохраняются для проверки. Автоматическая очистка и HTTP-удаление не реализованы. Если лимит достигнут, сначала сохраните отчёты; сброс служебного листа выполняется отдельно по явному решению владельца. Не меняйте JSON/заголовок вручную во время прогона.
- Это ограниченная проверка CAS и идемпотентности одной ячейки, не обещание транзакционности Sheets. При сбое Google или жёстком прерывании результат может быть неопределённым. Если создание листа оборвалось до заголовка, потребуется отдельная проверка владельцем; чужое или непонятное содержимое автоматически не перезаписывается.

Google рекомендует выполнять flush до освобождения блокировки при работе с таблицей: [Lock](https://developers.google.com/apps-script/reference/lock/lock), [SpreadsheetApp.flush](<https://developers.google.com/apps-script/reference/spreadsheet/spreadsheet-app#flush()>).

## Проверки и статус

Автоматические тесты покрывают конфликт двух ожидающих одну версию операций, повторы до и после нового изменения, изоляцию аккаунтов, неизвестный лист, повреждённые/дублирующиеся записи, лимит, ошибки flush и освобождение блокировки. В браузерном тесте первый ответ удерживается до получения второго запроса: последовательная отправка не смогла бы пройти этот сценарий. Проверяются экспорт отчёта, выход из аккаунта и мобильная ширина.

Тестовые адаптеры остаются отдельным доказательством. Реальный сценарий подтверждён [отчётом владельца](evidence/2026-09-03-concurrency-owner.json): восемь запросов, итоговая версия 2 и две операции, без дубликатов и отката старым повтором. Один прогон не является нагрузочным тестом или доказательством всех сбоев Sheets. Фото отдельно приняты владельцем 2026-09-03; возвращаться к ним пользователь не просит. Отзыв доступа и production-готовность этой пробой не подтверждаются.
