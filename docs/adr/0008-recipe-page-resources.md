# ADR 0008: Фото и стикеры в документе рецепта

Дата: 2026-09-05

## Ресурсы и права

Просмотр, дизайн и печать получают изображения через один ресурсный слой session API.
Ключ защищённого ресурса включает аккаунт, рецепт, конкретный photoId/instanceId и вариант файла;
digest не заменяет проверку доступа. Одновременные потребители разделяют запрос, а последний
закрытый потребитель отменяет загрузку и освобождает object URL. Logout, истечение сессии и отказ
доступа очищают пул; поздний ответ прежней сессии не возвращает ресурс в кэш. Токены и base64 в
хранилище браузера не записываются. Миниатюры фото запрашивают только `thumbnail`, оригинал —
только открытая страница/просмотр фото. Публичные Drive URL не используются.

Ошибка отдельного файла не скрывает успешно загруженные ресурсы. UI показывает отказ и явный
повтор; печать заблокирована до загрузки и декодирования всех разрешённых изображений. Каталог
паков и placement имеют разные основания доступа: приватный/архивный источник не даёт права
читать пак, но уже разрешённое активное размещение читается через recipeId + instanceId по
действующей серверной модели. Viewer не изменяет размещения.

## Координаты и совместимость

Ноль — левый верхний угол полного листа A4, включая поля. x/width — проценты ширины 210 мм,
y/height — проценты высоты 297 мм. Поворот — градусы вокруг центра прямоугольника стикера.
Порядок декора определяется zIndex; в DOM его слой равен 100 + zIndex, выше слоя содержания.
Изображение вписывается в прямоугольник с сохранением пропорций.

`page: N` и `pageId: page-N` — две записи одного устойчивого физического слота в пределах
recipeId. Это привязка к листу, а не к конкретному абзацу: текст при изменении может перейти
на другой лист. Ширина экрана, смена режима и reload ID не меняют. Новые команды передают
оба значения; сервер отклоняет противоречивую пару и сохраняет прежний числовой page.

Миграция старых размещений — чистый адаптер чтения `N → page-N`: не требует новой таблицы,
не меняет строк, revision, координат, recipeId или requestId. Повторное применение адаптера
даёт тот же результат; backup/restore сохраняет прежние строки. Переносимый формат v3 допускает
pageId и проверяет согласованность с page; прежние файлы без pageId принимаются.

Если документа больше нет на заданном листе, размещение остаётся в хранилище и списке стикеров,
но не рисуется на другой странице. UI объясняет проблему, блокирует печать и позволяет автору
явно выбрать существующий лист. Новые размещения выбирают ID из измеренного документа.

На телефоне страницы с декором показываются как масштабированные A4 с теми же координатами,
без растягивания координат по высоте потока чтения. Стикеры рисует общий renderer поверх
рецепта. Прежний пустой лист в StickerPacks заменён списком выбора и существующими кнопками
изменения размещения; свободного перемещения мышью нет.

## Фотографии

Обложка остаётся отдельным регионом opening-страницы. Фото шагов и галереи образуют bounded
photo-страницы после текста: один ресурс на страницу, заголовок/подпись и footer входят в
геометрию документа, изображение использует object-fit contain. Фото шага сохраняет stepId и
порядок внутри шага. Нет фото → нет дополнительных листов. Добавление фото не сдвигает
существующие текстовые страницы. Удалённый stepId даёт явную недействительную привязку и
блокировку печати; текст рецепта не дублируется в подписи.

Декоративный стикер имеет пустой alt и скрыт от дерева доступности; его выбор в управляющем
списке имеет осмысленное имя. Alt обложки включает название рецепта, alt фото шага/галереи —
название и номер шага/фото. Авторские произвольные подписи пока отсутствуют в photo API;
используется подпись из существующих данных, без выдуманного описания блюда.

Live deployment и миграции книги этим изменением не запускаются.
