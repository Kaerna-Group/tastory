# Проверка подключения Google staging

Дата: **2 сентября 2026 года**. Проверен опубликованный владельцем web app **Tastory API**, версия deployment **1**, метка приложения **staging-foundation**. Принадлежность URL текущему Google-проекту подтверждена через Apps Script API.

## Результаты

| Проверка                   | Результат               | Доказательство                                                                             |
| -------------------------- | ----------------------- | ------------------------------------------------------------------------------------------ |
| GET health с `/exec`       | Успешно                 | HTTP 200, JSON, `ok: true`, API v1, schema v0                                              |
| POST health                | Успешно                 | HTTP 200, совпадение requestId, `ok: true`                                                 |
| Redirect                   | Успешно                 | JSON получен после перехода на `script.googleusercontent.com`                              |

| React → Google из браузера | Успешно                 | В настройках Tastory показаны «Проверка связи с сервером Tastory» и «Соединение проверено» |
| Сборка staging             | Успешно                 | `npm run build:staging` с настоящим `/exec`                                                |

Клиент проверен во встроенном Chromium-браузере с origin `http://127.0.0.1:5178`. Использован обычный HTTP transport приложения: POST, `text/plain;charset=utf-8`, `credentials: omit`, `redirect: follow`. Схема ответа и совпадение requestId проверяются клиентом до отображения успешного соединения. Mock в этом запуске выключен.

Один контрольный прогон вне браузера: GET — 2939 мс, POST health — 2054 мс. Это единичные наблюдения, а не измерение p50/p95. Итоговый ответ содержал `Access-Control-Allow-Origin: *`; успех браузерного запроса дополнительно подтверждён интерфейсом приложения.

Конкретные URL и ответы сохранены локально в `.local/google-deployments.json`, `.local/google-api-check.json` и `.local/google-staging.json`. Эти файлы исключены из Git. Параметры web app в локальном manifest приведены к уже опубликованным владельцем: `USER_DEPLOYING`, `ANYONE_ANONYMOUS`. Удалённый исходный код в рамках подключения не изменялся.

## Отказ при входе вторым аккаунтом

3 сентября 2026 владелец передал [отчёт f075f489](evidence/2026-09-03-access-denied.json) в ответ на инструкцию войти вторым Google-аккаунтом без приглашения. Запись: `2026-09-03T08:48:43.167Z` — `2026-09-03T08:48:58.420Z` (UTC), 15.253 с вместе с действиями пользователя.

| Событие       | Результат                                                                | Длительность |
| ------------- | ------------------------------------------------------------------------ | ------------ |
| `signOut`     | Явный выход `account-1`, локальное событие                               | 0 мс         |
| `auth.signIn` | `denied`, `ACCESS_DENIED`, непустой requestId; account и role равны null | 2921 мс      |

Проверены строгая структура и допустимые поля, хронология, requestId и соответствие отметок событиям. **Отказ при входе со стороны Tastory подтверждён:** `deniedSignIn: true`. Это не ошибка сети, истечение токена или отказ Google до обращения к API. Выбранный при отказе аккаунт не получает псевдоним в отчёте; email, Google sub, credentials и тексты ошибок не экспортируются.

Связь с проверкой неприглашённого второго аккаунта основана на передаче файла в ответ на соответствующую инструкцию. Псевдоним `account-1` относится только к вышедшему аккаунту внутри этой записи, а не к отклонённому входу.

Повторный вход владельца остаётся принятым по отдельному отчёту выше: `repeatedSignIn: false` в новой записи не отменяет прежний результат. Отзыв уже допущенного участника и восстановление не проверялись; их отметки также `false`. Для следующего прогона нужен email второго аккаунта и временное приглашение `viewer`. Приглашение владельца и сохранённые привязки не меняются; [инструкция](google-access-staging.md#3-отзыв-у-тестового-участника-и-восстановление). Полный gate остаётся открытым.

## Ошибки при проверке читателя

3 сентября 2026 владелец передал [отчёт bd2d6f88](evidence/2026-09-03-access-unavailable.json) и текущий список `STAGING_INVITES` с одной записью owner. Файл сообщает origin `https://kaerna-group.github.io` и Chrome 152 на Windows. Запись длилась с `2026-09-03T09:00:56.464Z` до `2026-09-03T09:12:52.855Z` (UTC), 11 мин 56.391 с с паузами пользователя.

Обе попытки `auth.signIn` завершились `error / AUTH_UNAVAILABLE` за 4846 и 5607 мс. У каждой свой requestId, account и role равны null. Все четыре отметки `false` соответствуют записи: успешного входа, `auth.me`, отзыва и восстановления здесь нет. Структура, допустимые поля, хронология и requestId проверены; персональные данные в публичное доказательство не включены.

Присланный owner-only массив проверен настоящей `invitationsSchema` проекта. Локально `admitIdentity` для синтетической личности читателя и этого массива возвращает `ACCESS_DENIED`; с подготовленным массивом owner/viewer возвращает роль viewer. Оригинальная запись владельца сохранена без изменений. Это проверка предоставленного текста и локальной политики, не чтение или изменение свойств Google. Присутствие только owner сейчас не доказывает успешный отзыв ранее допущенного читателя.

Контроль опубликованного API в `2026-09-03T09:16:24.825Z` успешен: публичный health сообщает staging auth; запрос с синтетической неверной RSA-подписью и актуальным Google kid отклонён как `UNAUTHENTICATED` за 4057 мс. [Обезличенный результат](evidence/2026-09-03-auth-unavailable-live-check.json). Эта проверка не проходит до обработки приглашений проверенного пользователя, не проверяет `STAGING_AUTH_BINDINGS` и не воспроизводит прежний сбой.

**Причина `AUTH_UNAVAILABLE` не установлена.** В текущей реализации этот код объединяет ошибки получения/разбора ключей Google, ожидания блокировки, чтения/валидации свойств и сохранения новой привязки. Отсутствие приглашения само по себе даёт другой код. Сохранены локальные полный owner/viewer JSON и инструкция проверки существующей `setupStagingAuth`: функция проверит доступность ключей и формат приглашений, но не содержимое реестра привязок. До успешного входа читателя отзыв и восстановление не запускаются. Ранее принятые отчёты остаются историей; полный gate открыт.

## Как повторить

Локальная конфигурация `apps/web/.env.staging.local` уже заполнена. Из корня репозитория:

```sh
npm run dev:staging -- --port 5178 --strictPort
```

Откройте `http://127.0.0.1:5178/#/settings` и нажмите **Проверить снова**. Если сервер уже работает, повторно запускать его не нужно. Обычный `npm run dev` использует local/mock; для Google нужен `dev:staging`.

На другом компьютере сначала создайте `apps/web/.env.staging.local` по шаблону и укажите тот же опубликованный адрес в `VITE_API_URL`. Он не восстанавливается из Git автоматически.
