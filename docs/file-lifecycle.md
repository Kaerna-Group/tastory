# Жизненный цикл файлов

Рабочая копия содержит O-04 для файлов рецептов. Владелец видит раздел «Файлы книги» в настройках и может проверить связи, переместить доказанно неиспользуемые файлы в корзину Tastory, восстановить их или очистить корзину.

Проверка заново читает журнал и сохранённую историю рецептов. Для каждой версии фотографии она ожидает два приватных JPEG-файла: изображение и миниатюру. Поэтому фотография, удалённая из текущей версии рецепта, не считается неиспользуемой, пока она нужна для просмотра истории. Проверяются имя, размер, MIME-тип и SHA-256. Отчёт различает:

- исправные связанные файлы;
- потерянные файлы, на которые остаётся ссылка;
- повреждённые файлы и дубли одного имени;
- файлы Tastory, на которые нет ссылки ни в одной сохранённой версии;
- неизвестные файлы в папке книги;
- файлы в корзине Tastory.

Автоматическое перемещение разрешено только для файлов с подтверждённым состоянием «не используется». Неизвестные, повреждённые и связанные файлы инструмент не удаляет. Перед каждым изменением сервер повторяет сканирование под общей блокировкой и заново проверяет текущую роль владельца.

Корзина Tastory — приватная вложенная папка в папке книги. Восстановление возвращает файл в корень только при отсутствии конфликта имени. Очистка отправляет содержимое этой папки в корзину Google Drive; после этого автоматическое восстановление в Tastory недоступно. Вложенная корзина входит в резервную копию книги, пока её не очистили.

HTTP-действия используют прежний envelope API v1: `admin.files.audit`, `admin.files.trash`, `admin.files.trashUnused`, `admin.files.restore`, `admin.files.cleanup`. Все они доступны только фактическому владельцу по свежему состоянию WorkspaceMembers.
