# Замеры Google staging

Инструмент для S0-09: повторяемая исходная выборка задержек публичного API. Запускается с компьютера разработчика в Node.js; авторизованные операции и браузерный CORS оцениваются отдельно.

## Первый результат — 3 сентября 2026

Прогон выполнен `2026-09-03T07:40:47.341Z`—`07:44:44.733Z`, Windows x64, Node.js 24.14.0. Google API во время прогона подтвердил опубликованную version 4 (`91ecc9f`, проверка `07:43:59.380Z`). Проверяемый сервер не изменялся.

**59 из 60 измеряемых запросов успешны; один echo превысил 15 секунд.** Все три прогрева успешны и исключены из таблицы задержек. Серия завершена (`complete: true`), но итог неуспешен (`passed: false`, код завершения 1); сбой не заменялся повторным запросом.

| Сценарий     | Успехи / попытки | Тело запроса / ответа, байт | p50, мс | p95, мс | Минимум—максимум успехов, мс |
| ------------ | ---------------- | --------------------------- | ------- | ------- | ---------------------------- |
| Health       | 20 / 20          | 98 / 275                    | 3427    | 4712    | 1940—5114                    |
| Echo ASCII   | 19 / 20          | 1132 / 1150                 | 3258    | 4273    | 1883—4273                    |
| Echo Unicode | 20 / 20          | 3180 / 3198                 | 3882    | 5228    | 2376—5299                    |

В строке ASCII задержки относятся только к 19 успешным ответам. Ошибочный запрос был остановлен через 15004 мс; это время ожидания до таймаута, не известное время завершения сервера. Из этой выборки нельзя установить причину единичного сбоя или заключить, что 95% всех запросов укладываются в указанный p95 успехов.

[Все измерения JSON](evidence/2026-09-03-transport-baseline.json). Инструмент запускался из рабочей копии поверх `5513904`; незакоммиченные изменения честно отмечены в отчёте, точная сборка инструмента связана с SHA-256. Это не утверждение, что benchmark уже присутствовал в `5513904`.

Практический вывод: небольшие публичные запросы в этой выборке обычно требуют нескольких секунд; текущий таймаут 15 секунд сработал один раз. Таймауты приложения по одному наблюдению не меняем. S0-09 закрыт только в части исходной выборки небольших запросов, полный gate открыт.

## Авторизованные операции — отчёт владельца

Владелец предоставил [успешный прогон конкурентных записей](staging-verification.md#настоящий-прогон-одновременных-записей): восемь запросов за 40.689 с, каждый занял 4147–7305 мс. Это чтения, новые записи, конфликт и повторы; их задержки не объединяем с публичным health/echo и не объявляем восемь разнородных запросов устойчивой выборкой p95.

По временным меткам прогон владельца `07:41:04Z`—`07:41:45Z` пересекался с началом benchmark. Параметр `concurrency: 1` относится к собственному потоку benchmark; в это время сервер мог обслуживать и запросы владельца. Исходная выборка не является замером изолированного сервера без другой нагрузки. Из совпадения времени нельзя выводить причину единичного таймаута.

## Запуск

Из корня репозитория после `npm ci`:

```sh
npm run benchmark:staging
```

Адрес берётся из `STAGING_API_URL`, а при отсутствии переменной — из `VITE_API_URL` в `apps/web/.env.staging.local`. Принимается только опубликованный HTTPS `/exec` Google Apps Script. Google-вход не требуется. Для echo в рабочем staging уже включён `ENABLE_SPIKE_ECHO`.

По умолчанию выполняются три прогрева и 60 измеряемых запросов: по 20 на каждый сценарий. Запросы идут последовательно, сценарии чередуются; автоматических повторов нет. Обычно запуск занимает несколько минут. Для короткой диагностики:

```sh
npm run benchmark:staging -- --samples=5
```

Допустимо 1–20 измерений на сценарий. Таймаут одного запроса — 15 секунд, включая чтение ответа. Ошибка при прогреве или три последовательные ошибки останавливают запуск с неполным отчётом. Любая ошибка делает результат неуспешным и код завершения ненулевым; она не теряется при подсчёте успешных запросов.

## Что измеряется

| Сценарий            | Данные                                     |
| ------------------- | ------------------------------------------ |
| `health`            | Обычная проверка связи, пустой payload     |
| `echo-ascii-1024`   | 1024 символа ASCII, 1024 байта текста      |
| `echo-unicode-1024` | 1024 символа `界`, 3072 байта текста UTF-8 |

Число символов одинаково; реальные размеры всего JSON-запроса и ответа записываются в байтах UTF-8. Это размеры несжатых тел, без сетевых заголовков, TLS и расходов на перенаправление.

Время отсчитывается от отправки POST до полного чтения и проверки JSON, включая Google redirect. Обязательны HTTP 200, конечный origin `script.googleusercontent.com`, контракт ответа, совпадение requestId, `auth: staging` у health и точное содержимое echo.

Для каждого сценария считаются число успешных/ошибочных измерений, минимум, медиана, p95 и максимум. Используется nearest-rank: элемент `ceil(p × n)` отсортированной выборки успешных измерений, нумерация от 1. Прогревы и ошибки исключаются из задержек, но сохраняются отдельными записями. Если успехов нет, задержки равны `null`, а не нулю. При 20 успехах p95 — 19-е значение; такой небольшой прогон не доказывает SLA или устойчивость хвоста распределения.

## Отчёт

Каждый запуск создаёт новый JSON в `.local/benchmarks/` с UTC-временем в имени. Там есть все измерения, runtime, ОС, параметры запуска, текущий Git commit, признак незакоммиченных изменений и SHA-256 собранного инструмента. В отчёт не попадают токены, аккаунты, содержимое ответов, URL с параметрами и приватные идентификаторы Google-ресурсов.

Исходные локальные отчёты игнорируются Git. Проверенную обезличенную выборку можно сохранить в `docs/evidence/` и связать с версией API в этом документе.

## Границы результата

Это исходная характеристика небольших запросов к публичному API из Node.js. Она не измеряет авторизацию, блокировки или сохранение в Sheets, не заменяет проверку CORS в браузерах и не устанавливает максимальный размер входящего запроса Apps Script. Лимит echo в 1024 символа — правило приложения.

Фото уже приняты владельцем. Этот инструмент не обращается к фотографиям и не требует повторять их проверку. Решение о способе загрузки не следует выводить из задержек небольшого echo. [Настоящий прогон одновременных записей](google-concurrency-staging.md) принят; общий gate платформы остаётся открытым до остальных сценариев доступа и архитектурных решений.
