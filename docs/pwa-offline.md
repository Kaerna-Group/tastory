# PWA и ограниченная работа без сети

Web-сборка Tastory устанавливается как приложение в браузерах с поддержкой PWA. Manifest использует относительные `start_url` и `scope`, поэтому установка работает как с корня домена, так и из каталога GitHub Pages.

Когда браузер подтверждает возможность установки, приложение показывает компактное приглашение. Его можно закрыть; решение сохраняется локально и приглашение не перекрывает основное содержимое. Системный диалог открывается только по кнопке пользователя.

Во время сборки создаётся `sw.js` с версией, зависящей от имён собранных файлов. Service worker заранее сохраняет оболочку приложения, стили, код и основные иконки. Переходы HashRouter после первого успешного открытия доступны без сети. Серверные запросы и ответы Google Apps Script не попадают в этот кеш.

После входа библиотека сохраняет до 50 последних сводок и до 12 открытых рецептов отдельно для каждого сочетания API и аккаунта. При недоступном сервере библиотека показывает этот снимок. Рецепт из кеша открывается только для чтения, пока сервер снова не подтвердит права. Уже созданные локальные черновики продолжают редактироваться без сети; очередь отправляется при следующем открытии с подключением.

Новая версия service worker не получает доступ к ответам API и не смешивает данные аккаунтов. Обновление оболочки применяется браузером по жизненному циклу service worker; приложение не подменяет этот процесс оптимистичной подписью. Если рецепт сохранился лишь в памяти вкладки, пользователь должен сначала сохранить или скачать аварийную копию. Обычные локальные черновики находятся в `localStorage` и переживают обновление.

Ограничения MVP:

- первый запуск и вход требуют сети;
- серверные права не считаются действительными без свежей проверки;
- изображения рецептов не включаются в гарантированный офлайн-набор;
- браузер может очистить локальные данные по своей политике хранения, поэтому ценные несохранённые версии следует отправлять на сервер или скачивать.
