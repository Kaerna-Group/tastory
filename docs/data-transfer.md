# Импорт и экспорт рецептов — X-01, базовый формат

Реализовано в рабочей копии 4 сентября 2026. Формат переносит текущие состояния рецептов, их ингредиенты, шаги, теги, заметки, видимость, оригиналы фотографий и миниатюры. Публикация и проверка на настоящей Google-книге остаются этапом выпуска.

## Формат

Файл имеет расширение `.tastory.json`, маркер `tastory.recipe-book` и номер версии `1`. Один и тот же строгий JSON-конверт используется для одного рецепта и книги. Прикладные данные не содержат номеров строк Google Sheets, идентификаторов Drive, владельца исходной книги или квитанций внутренних операций.

Для каждого рецепта сохраняются:

- содержимое, ингредиенты и шаги с исходными идентификаторами только для восстановления внутренних связей;
- названия и цвета тегов;
- видимость и исходное состояние для предпросмотра;
- обложка, галерея и фотографии шагов вместе с размерами, SHA-256, оригиналом и миниатюрой в base64.

Максимальный размер одного файла — 250 МБ. Лимиты самого рецепта и фотографий совпадают с действующими контрактами Tastory. Большую коллекцию следует переносить несколькими файлами рецептов; архив истории, участники, аудит, избранное и резервные копии в переносимый формат версии 1 не входят.

## Экспорт

Сохранённый рецепт экспортируется кнопкой **Экспортировать с фото** в редакторе. Кнопка не запускается, пока локальные правки или конфликт не завершены. Владелец может экспортировать все доступные ему рецепты кнопкой **Экспортировать книгу с файлами** в настройках.

Перед скачиванием приложение заново читает текущий рецепт и каждую связанную фотографию через защищённый API. Сервер проверяет права, расположение файла в приватной папке и SHA-256. Отсутствующая или повреждённая фотография останавливает экспорт: неполный файл не предлагается пользователю как готовая книга.

## Предварительный просмотр и импорт

Файл сначала целиком разбирается строгой схемой. До первой записи проверяются версия, размеры, уникальность объектов, ссылки фотографий на шаги, порядок фотографий, фактическое число байтов и SHA-256 обоих вариантов каждого изображения. Затем показываются количество рецептов, ингредиентов, шагов и фотографий, а также совпадения названий с текущей библиотекой.

Для совпадений доступны два режима:

- пропустить рецепты, название которых уже есть в библиотеке;
- создать отдельные рецепты с тем же названием и новыми идентификаторами.

По умолчанию все импортируемые рецепты становятся личными. Пользователь может явно сохранить видимость `private/workspace` из файла. Рецепты создаются как черновики: исходные состояния `published/archived` остаются в файле для предпросмотра, но не применяются без отдельного действия жизненного цикла.

Теги сопоставляются по нормализованному названию; отсутствующие создаются с сохранением цвета. После создания рецепта фотографии добавляются в прежние группы и позиции, а фотографии шагов привязываются к новым идентификаторам соответствующих шагов.

## Повторы и границы доверия

Для выбранного файла браузер хранит только случайный ID запуска, привязанный к SHA-256 файла, аккаунту, серверу и политике видимости. Из него выводятся устойчивые request ID для рецептов, тегов и фотографий. После обрыва повтор возвращает прежние квитанции и продолжает с первой отсутствующей фотографии, не создавая дубль. Содержимое импортируемого файла в localStorage не записывается.

Кнопка **Подготовить ещё одну копию** удаляет ID завершённого запуска и явно начинает новый перенос. Смена политики видимости также использует отдельный запуск, поэтому один request ID никогда не получает другое содержимое.

Файл считается недоверенным вводом. Он не может задать владельца, workspace, серверные даты, ревизии, Drive ID или идентификаторы новых объектов. Все права, лимиты, ссылки на теги и ожидаемые ревизии повторно проверяются сервером обычными действиями `recipes.create`, `recipes.photos.add` и `tags.create`.

## Проверка

Контрактные тесты отклоняют дубли и неверные связи фотографий. Модель переноса проверяет экспорт оригинала и миниатюры, повреждение SHA-256, предпросмотр совпадения, личную видимость по умолчанию, перенос фотографии шага и повтор без дублей. Браузерный сценарий проверяет выбор файла, предпросмотр, импорт и скачивание книги в production-сборке.

Следующее расширение X-01 добавит историю версий и остальные сущности книги после появления их переносимых контрактов. Для очень больших коллекций нужен потоковый архив или серверная подготовка нескольких частей с учётом квот Google.
